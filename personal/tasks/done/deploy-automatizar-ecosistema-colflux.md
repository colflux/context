# Automatizar despliegue continuo de todo el ecosistema COLFLUX

**Estado:** cerrada
**Creada:** 2026-09-07
**Cerrada:** 2026-09-15

## Objetivo

Que **todos los repositorios de COLFLUX con servicio en ejecución** (según [[repositorios]]: `backend`, `frontend`, y `ia-functions` cuando tenga commits) se desplieguen automáticamente al servidor `44.213.47.34` cada vez que se hace push a `main`, sin pasos manuales.

## Contexto

La tarea nació enfocada solo en el frontend (revisar opciones de GitHub Actions/Pages para su despliegue automático), tomando como referencia la publicación automática de este repo de documentación en GitHub Pages (ver README.md).

El alcance se amplió el 2026-09-07, durante [[subir-datos-ideam-servidor]]: al migrar las fuentes IDEAM/SWAMP de local al servidor `44.213.47.34`, se descubrió que **el backend de ese servidor también está desactualizado**, no solo el frontend. Se crearon los proyectos y las 7 fuentes de datos vía API (`/api/proyectos/crear/`, `/api/fuentes-datos/crear/`) y se subieron los 7 archivos (5 Excel IDEAM + 2 CSV SWAMP), pero **solo 1 de las 7 fuentes se pudo importar** (SWAMP CH4: 1162 registros de `SubmuestraGEI`, 147 `MuestraGEI`, 76 `UnidadMuestreo` nuevas). Las otras 6 quedaron creadas en el servidor pero sin datos importados, bloqueadas por:

1. **Las 5 fuentes IDEAM** fallan con `Cobertura has no field named 'cobertura_ipcc'` — el servidor remoto corre una versión del backend **anterior al commit que agregó los modelos `Cobertura`/`Disturbio`/`Vegetacion`** (commit `d289749`, "Add new fields and models for biomass and organic matter measurements"). `GET /api/etl/campos-destino/` en el remoto ni siquiera lista esos modelos.
2. **SWAMP Flujos CO2** (1653 filas) falla por timeout del worker de gunicorn a los 30s exactos al intentar previsualizar/importar — es un límite de configuración del servidor, no un problema de datos.

Esto evidenció que el problema no es solo del frontend: cualquier repo con servicio en ese servidor puede quedar desactualizado silenciosamente si no hay despliegue automático. De ahí que la tarea se redefina a nivel de **todo el ecosistema**.

El 2026-09-08 se confirmó con Viviana que: el servidor corre los servicios vía **Docker Compose**, y el acceso SSH al servidor hoy lo tiene **Daniel** (compañero de equipo), no Viviana — es un bloqueante para arrancar la automatización.

`context` y `wiki` no aplican a esta tarea — no corren servicio en `44.213.47.34`; `context` ya se publica solo vía GitHub Pages.

**Actualización 2026-09-09:** el bloqueante de acceso SSH ya no aplica — Viviana sí tiene acceso al servidor vía la consola SSH del navegador de Lightsail (no necesitó la llave de Daniel). Se avanzó completo el punto 2 y el `backend` del punto 3 del plan (ver Historial).
