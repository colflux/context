# Requerimientos

Un requisito describe el **qué** debe hacer el sistema, de forma verificable — no el **cómo** se implementa (eso va en [Arquitectura](../arquitectura/index.md)).

El [catálogo de funcionalidades](funcionalidades/index.md) consolida el Anexo 1, el Anexo 2, los talleres de co-diseño y el Marco Teórico. Está marcado como **borrador**: falta la revisión de viabilidad y la retroalimentación del equipo antes de darlo por confirmado — el seguimiento de ese trabajo vive en `tasks/backlog/arquitectura-lista-funcionalidades.md`.

Para una necesidad nueva que todavía no tiene código ni encaja en el catálogo consolidado, se especifica como [requerimiento](requerimientos/index.md) siguiendo la plantilla SMART de [¿Cómo crear buenos requerimientos?](requerimientos/buenos-requerimientos.md).
